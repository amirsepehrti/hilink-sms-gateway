# رفتار تأییدشده‌ی مودم

این نکات با تست روی مودم واقعی Huawei E303 (HiLink، فریم‌ور `22.318.27.00.00`) به‌دست آمده‌اند.
روی مدل یا فریم‌ور دیگر فرض نکن، تست کن.

| مورد | واقعیت |
|---|---|
| احراز هویت | API مودم هیچ احراز هویتی ندارد؛ شبکه‌اش را route نکن |
| توکن | `/api/webserver/token` کار می‌کند و **یک‌بارمصرف** است؛ قبل از هر درخواست تازه بگیر |
| هم‌زمانی | مودم بیش از یک عملیات SMS قبول نمی‌کند (`113018`)؛ همه‌ی تماس‌ها باید از یک مسیر بروند |
| ظرفیت | `LocalMax=500` برای جمع ورودی، ارسالی و پیش‌نویس |
| حافظه‌ی پر | **دریافت پیامک بی‌صدا متوقف می‌شود** ولی ارسال همچنان `OK` می‌دهد |
| ایندکس | بعد از خالی شدن کامل حافظه از نو شروع می‌شود؛ هویت پیام = ایندکس + فرستنده + زمان |
| پیام بلند | تکه‌ها جدا می‌رسند و متن یک ایندکس کامل‌تر می‌شود |
| گزارش تحویل | پشتیبانی واقعی ندارد؛ `Smstat` همیشه `3` است |
| USSD | پنجره‌ی پاسخ کوتاه است (هر ۰٫۳ ثانیه poll) و `111019` یعنی «هنوز آماده نیست» |
| منوی USSD | ممکن است جداکننده نداشته باشد: `1پرداخت` |

## آینه‌سازی یک‌طرفه

فقط پیام‌های ورودی از مودم در آرشیو آینه می‌شوند. پیام خروجی هنگام ارسال با `modem_index = NULL`
ثبت می‌شود، چون آینه کردن صندوق ارسالی هر پیام را دوبار ثبت می‌کرد و dedupe بر اساس شماره، متن و
زمان شکننده است. پیامی که خارج از این گیت‌وی فرستاده شود در مکالمات دیده نمی‌شود.

کلید یکتای `(direction, modem_index)` باید بماند؛ همین کلید است که جلوی رکورد تکراری را می‌گیرد.
